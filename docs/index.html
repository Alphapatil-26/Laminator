Visual feedback.
For agents.

Laminator turns a click on your running app into structured context an AI coding agent can act on — the exact file and line that paints the thing you pointed at, what the rule currently declares, and how many other elements it moves.

npm i -D laminator
localhost:5173
## Annotation #1 — h2 Feedback: these cards feel cramped Intent: fix · Severity: important Rule: `.bean-name` — styles/cards.css:3 Applies to: 3 elements on this page — an edit here moves all of them Where: section.card-grid > article.bean-card > h2.bean-name Computed: font-size: 19px; margin: 0px 0px 4px; line-height: 26.6px

How you use it

  1. Run npx laminator init — it scans your project and prints one script tag
  2. Add that tag to your app — development only
  3. Press Ctrl/Cmd+Shift+F — the toolbar appears bottom-right
  4. Click any element and write what is wrong — or dictate it
  5. Press Send — your agent opens with the whole batch

Entirely local. One Node process bound to 127.0.0.1, zero npm dependencies, no account, no telemetry. Nothing leaves your machine.

Install

# in your project root
npm install --save-dev laminator
npx laminator init

Then add the printed line to your app, guarded so it never ships:

Capture modes

ModeKeyWhat it captures
PickEOne element — its rule, computed styles, component chain, and any neighbour whose edge misses by 0.4–6px
TextTThe exact copy you selected, plus the element holding it
MultiMSeveral elements at once. Press M again to comment on them together
AreaAA dragged region — the container plus everything inside it
FreezePPauses every animation and transition so you can annotate one frame
ShotsAttaches a real screenshot of the element, cropped with 48px of surroundings

The comment box takes dictation too, where the browser supports it.

Dictation uses the browser's speech API, which on Chrome sends audio to Google. It is opt-in per use and the button says so. Nothing else in Laminator touches the network.

What it can anchor

This decides how useful a finding is, so Laminator says which case it is rather than guessing:

SaysMeansThe agent gets
ruleAn authored stylesheet rule paints itThe exact file:line, its declarations, and how many elements it moves
utilityTailwind or similar — there is no ruleThe class list and the component, so it edits the markup
noneCSS module, <style> block, or CSS-in-JSThe class list to search for

CSS modules are excluded on purpose. Their class names are hashed at build time, so a selector seen in the browser cannot be traced back to source. An anchor there would look right and point nowhere.

Handing off

Send writes the batch and opens your agent on it. Four choices under Setup → Open in:

  • New chat — a fresh session, so the review does not interleave with what you were doing
  • Continue last — a new window carrying your most recent conversation
  • A named session — a new window carrying that specific conversation
  • Copy only — writes the file, opens nothing, puts the prompt on your clipboard

Nothing can type into a terminal that is already running. No agent CLI has a way in, and Claude Code's --resume on a live session starts a copy. So "send it to the terminal I already have open" is Copy only plus a paste — and Laminator says so rather than pretending otherwise.

As your agent resolves findings, the pins go grey while you watch. The queue is shared and the page polls it every three seconds.

Output

Every Send writes two files into .laminator/ — markdown for reading, JSON for parsing:

# .laminator/review-2026-09-09T20-17-00.md
## Annotation #1 — h2

**Feedback:** these cards feel cramped
**Intent:** fix · **Severity:** important

**Rule:** `.bean-name` — styles/cards.css:3
**Applies to:** 3 elements on this page — an edit here moves all of them

**Where:** section.card-grid > article.bean-card > h2.bean-name
**Page:** /
**Computed:** font-size: 19px; margin: 0px 0px 4px

A standing brief you write once appears above the findings, because it changes how they should be read.

CLI

laminator init      # scan, write the command file, print the snippet
laminator           # serve (scans first if it never has)
laminator scan      # re-read the project after moving CSS around
laminator doctor    # what it found, and what it could not

  --root DIR        # project to work on   (default: cwd)
  --port N          # sidecar port         (default: 7317)

HTTP API

Everything the overlay does is a plain HTTP call your agent can make too.

EndpointWhat it does
GET /queueThe live findings
POST /queueadd, update, reply, delete, clear, export, savings
POST /rulesCandidate rules for a set of selector tokens
POST /cssChange one declaration in one rule
GET /configWhat the scan found
GET /sessionsLive agent conversations to hand off to
# close a finding — the pin greys out in the browser within 3s
curl -s -X POST -H "content-type: application/json" \
  -d '{"action":"update","id":"ann_…","patch":{"status":"resolved"}}' \
  http://127.0.0.1:7317/queue

Requests carrying an Origin must come from localhost and present x-laminator-token. Requests with no Origin — your agent's curl — are local processes and are allowed. See Privacy for why.

Config

.laminator/config.json is plain JSON, meant to be read and argued with. The overrides block survives a re-scan; everything else is regenerated.

{
  "overrides": {
    "surfaceRoot":   "",   // selector for your app's main container
    "includeStyles": [],   // stylesheets the scan missed
    "excludeStyles": []    // stylesheets it must never write to
  }
}

Privacy and safety

  • Binds to 127.0.0.1 only — never 0.0.0.0, so nothing on your network reaches it.
  • Zero dependencies. Nothing is fetched at install beyond the package itself.
  • Any page you visit can send a request to localhost — the browser blocks it from reading the reply, but not from making it. Since this server writes stylesheets, every mutating request from a page must carry a token minted at init, and the script carrying it is only served to localhost origins.
  • The write endpoint takes a file, a line, a property and a value. There is no free-text write, and the file must be one the scan listed as editable.
  • .laminator/ carries its own .gitignore of *.

FAQ

Does this work without an AI agent?

Yes. Send writes the review file and copies the prompt whatever you have installed. The agent is the convenience, not the requirement.

My project is all Tailwind. Is it useless?

No, but be clear-eyed: there is no rule to point at, so findings come back as utility with the class list, the component name and the computed styles. That is still far more than a screenshot.

It says "no authored rule" for everything.

Run laminator doctor. If it reports 0 editable stylesheets, the scan found none — add them to overrides.includeStyles and re-scan.

A finding points at the wrong line.

The stylesheet changed since the scan. Run laminator scan.

Can I self-host these docs?

They are one static HTML file in site/. npm run site serves it; it deploys to Railway, Vercel, Netlify or any static host unchanged.
