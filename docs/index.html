The annoying part

Describing UI is slow. Pointing isn't.

You can spend three messages explaining which heading, on which page, in which state. Or you can click it. Laminator reads the page, works out which rule paints what you clicked, and writes it down properly.

Install

Two commands and one line

Run it in your project. It reads the repo, finds your stylesheets and prints a script tag. Add that tag in development only.

Pointing

Four ways to say "this bit"

Pick E

One element. You get its rule, its computed styles, its component, and any neighbour whose edge misses by a couple of pixels.

Text T

Select some copy. The exact words come through, so nobody has to guess which sentence you meant.

Multi M

Click several things. Press M again and they become one comment about all of them.

Area A

Drag a box. You get the container plus everything inside it, for when the problem is the arrangement.

Freeze P

Stops every animation so you can annotate the frame that's actually wrong.

Shots

Attaches a real screenshot of the element, with room around it so the spacing is visible.

You can dictate the comment instead of typing it. On Chrome that sends audio to Google's speech service, so it's off until you press the button, and the button says so. Nothing else here touches the network.

Honesty

Sometimes there's no line to point at

Not every element comes from a stylesheet you can open. Laminator says which case it's in instead of guessing.

rule

A stylesheet rule paints it. Your agent gets the file, the line, what it currently declares, and how many elements share it.

utility

Tailwind, or something like it. There's no rule to edit, so you get the class list and the component name instead.

none

A CSS module, a style block, or CSS-in-JS. You get the classes to search for.

CSS modules are left out of the index on purpose. Their class names are hashed when you build, so a selector in the browser can't be traced back to the source. An anchor there would look right and point nowhere.

Handoff

Send, then watch the list drain

Send writes the batch and opens your agent on it. As it fixes each one, that pin goes grey in your browser. You don't wait for a summary.

New chat

A fresh session, so the review doesn't get tangled up in whatever you were doing.

Continue last

A new window carrying your most recent conversation.

A named session

A new window carrying that specific conversation.

Copy only

Writes the file, opens nothing, puts the prompt on your clipboard.

Nothing can type into a terminal that's already running. No CLI has a way in, and Claude Code's --resume on a live session starts a copy of it. So "send it to the window I've already got open" is Copy only, then paste.

Safety

It stays on your machine

Local only

The server binds to 127.0.0.1. Not 0.0.0.0, so nothing on your network can reach it.

No dependencies

Zero npm packages. Nothing is fetched at install beyond Laminator itself.

Token on writes

Any page you visit can fire a request at localhost. The browser stops it reading the reply, but not sending it — so anything that writes needs a token, and the script carrying that token is only served to localhost.

Narrow writes

The write endpoint takes a file, a line, a property and a value. There's no free-text write, and the file has to be one the scan listed.

Out of your diffs

.laminator/ ships its own gitignore.
